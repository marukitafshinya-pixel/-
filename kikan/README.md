# 基幹システム Web 版（Access からの移行）

Access で作った基幹システム 8 つ（受注登録・丸北WorkStation・倉庫管理System・製造管理 丸北・製造計画・包装場管理System・WEB連携・手配出力用カレンダー）を、クラウドで動く Web アプリに移すためのフォルダ。

- 調査と計画：[../docs/access移行/](../docs/access移行/00_全体像.md)
- 進め方：[移行計画](../docs/access移行/10_移行計画（案）.md)

## フォルダ

| フォルダ | 中身 |
|---|---|
| `migrate/` | Access のデータを PostgreSQL に移す道具 |

## データの移し替え（migrate）

1. Access のファイルを `migrate/data/` に置く（ファイル名は `migrate/sources.json` のとおり）。このフォルダはリポジトリに入れない。
2. PostgreSQL を用意し、次を実行する。

```
cd kikan/migrate
PGURL=postgresql://ユーザー@ホスト/データベース python3 accdb_to_pg.py sources.json
```

- Access ファイル 1 つが、PostgreSQL のスキーマ 1 つになる（例：丸北WorkStation.accdb → `ws`）。
- 表と項目の名前は Access と同じ（`ws."TD_出荷"."輸送ID"` のように二重引用符で囲んで使う）。
- 何度でもやり直せる（実行のたびに、そのスキーマを作り直す）。
- 結果は `移し替え結果.md` に出る（表ごとに Access の件数と移した件数を比べる）。
- 必要なもの：mdbtools（`mdb-tables`・`mdb-schema`・`mdb-export`）、psql、Python 3。

## 書き出した CSV からの取り込み（csv_to_pg）

Access の画面側ファイルで `ExportTables`（表を CSV と fields.txt に書き出すプログラム）を動かして作ったフォルダを取り込む。

```
cd kikan/migrate
PGURL=... python3 csv_to_pg.py --fe 受注登録FE --dir 書き出したフォルダ
```

- fields.txt の型で表を作り、同じ名前の CSV を入れる。
- リンクしている表は、本来の持ち主のスキーマに入れる（例：受注登録FE の「TD_出庫」→ `soko."TD_出荷"`）。対応は `links/画面側ファイル名.json`（画面側ファイルの中の情報から作ったもの）。
- 画面側ファイルの中の表は、`sources.json` でその画面側ファイルに割り当てたスキーマ（例：`juchu_fe`）に入れる。
- ほかのシステムの表がいっしょに書き出されていて、すでに取り込んだものを上書きしたくないときは `--skip-schemas ws,soko` のように指定する。

## Excel で保存した CSV からの取り込み（excel_csv_to_pg）

Access の表を Excel に貼り付けて CSV にしたもの（型の情報がないもの）は、同じ形の表の型を借りて入れる。

```
PGURL=... python3 excel_csv_to_pg.py --csv 倉庫管理の受注.csv --table soko.TD_受注 --like juchu.TD_受注
PGURL=... python3 excel_csv_to_pg.py --csv 転売品管理の受注.csv --table tenbai.TD_受注 --like juchu.TD_受注
```

- 日付（13-Oct-26 など）・TRUE/FALSE・カンマ付きの数字を読み替える。入れる前に表を作り直す。

## Web アプリ（app）

| フォルダ | 中身 |
|---|---|
| `app/server/` | サーバー（Fastify・PostgreSQL）。ログイン、受注の API |
| `app/client/` | 画面（React）。Access の画面に近い見た目にしている |

```
cd kikan/app
npm install
npm run build                      # 画面を作る（dist/）
PGURL=... npm run create-user -- ログインID 名前 パスワード [admin]
PGURL=... npm start                # http://localhost:3000 で開く
```

- 表は Access と同じ名前のものを使う（例：`juchu."TD_受注"`）。Web 版だけで使う表（利用者・ログイン・設定）は `app` スキーマに置く（`server/schema.sql`）。
- 開発中は `npm run dev`（画面は http://localhost:5173）。
- 受注の削除には、Access と同じく合言葉が要る。合言葉はプログラムに書かず、サーバーを動かすときに `JUCHU_DELETE_PASSWORD` で渡す（今の Access と同じものにする。2026/10/20 確認）。渡していないときは削除できない。

### できている画面
- ログイン、メニュー（受注管理）
- 受注先選択画面（FM_受注先選択画面）
- 受注検索（F_受注検索）：検索と、チェック（完了消込・入力確認〜送品案内）の付け外し。押すとすぐ保存される
  - 「出力」：いま表示している条件の受注を Excel（受注検索.xlsx）にする。Access の出力と同じ 15 列・同じ見た目（見出しは太字・灰色、日付は 14-Oct-26 の形）で、受注ID の順。Access では「当日入力分」「キャンセル未処理」を押したあとの出力は前の条件のままになるが、Web 版は表示しているとおりに出す
  - 「入力確認」を押すと、付けても外しても、受注特定項目の備考があれば備考の前に足し、入力日を今日にする（Access と同じ。何度も押すと備考が重なるのも今のまま）。
- 販盛受注取込み（F_販盛インポート）：販盛からダウンロードした「受注実績一覧」の CSV を「ファイル参照」で読み込む。Access と同じ動き：
  - 開いたときに前の読み込み（T_販盛受注）を消す。読み込むと、販盛の伝票番号＋行、または重さ・受注番号・納品日で Access の受注と結びつけ、結びついていないものだけを出す。
  - 「選択」を付けて「受注取込み」で受注に入れる（商品は繁盛商品コード、届け先は繁盛納入先コードで読み替え。読込変換届け先コードを入れればそれを使う。隠語「販盛In」）。
  - Access と同じく、取り込み済みかどうかは確かめずに入れる（同じ行を 2 回取り込むと 2 件になる）。
  - 販盛のサイトからのダウンロード（販盛受注出力）は、社内のパソコンの自動入力で行う予定（準備中）。
- 販盛売上出力（F_販盛インポート売上）：「売上実績一覧」の CSV を読み込み、販盛の売上番号・行を受注に結びつける。一覧は受注日が 7 日前からの受注。販盛のサイトからのダウンロードと、販盛への売上の自動入力は、社内のパソコンで行う予定（準備中）。
- 新しく入れる受注の既定値：Access の表の既定値に合わせ、初回登録chk はなし（「入力確認」を押したときに入る）、入庫名義ID 1、受注グループID 0、残ケース 0 など。登録時間は Access と同じ形（2026/10/09 9:02:01）。
- 受注訂正（FM_受注訂正）：受注検索で処理コード（TM_枝処理マスタ：00 通常・0１ 訂正入力・02 追加受注・03 キャンセル・99 その他）を 0１〜03 にすると開く。Access と同じ動き：
  - 「閉じる」で、右の訂正の値をこの受注・WorkStation／倉庫管理／転売品管理の受注の写しに書き、まだ確定していない出荷（chk なし）に「受注訂正」の知らせを立てる。「やめる」は何もしないで閉じる。
  - 備考の先頭に「どこを直したか＋に訂正」を足す。いくつ直しても、最後に見つかった 1 か所だけが書かれる。
  - 引き取り区分の訂正の欄は空欄で始まる（選ばなければ今のまま）。
  - 隠語は、Access では訂正のたびに消えていた（「販盛In」の印がなくなる）が、Web 版では残す（2026/10/20 確認。不具合の例外として直した）。
  - Access の「TD_受注_訂正履歴」は表がなく、今も書かれていないため、Web 版でも書かない。
  - 倉庫管理・転売品管理の受注の写し（TD_受注）は、利用者から受け取った CSV で取り込み済み（2026/10/20：倉庫 178 件・転売 126 件）。転売品管理はごくまれに使うので、転売品管理の写しを直す動きも残す（2026/10/20 確認）。
- 受注登録（FM_受注登録_届け先指定）：新しい受注の入力・直し・削除。Access と同じ動き：
  - 受注番号・届け先コード・商品コード・ケース・商品kg・納品予定日を 2 回打って、違っていれば保存しない（片方が空欄のときは確かめない。Access と同じ）。
  - 受注番号が空欄なら「年月日＋商品コード＋届け先コード」で作るか聞く。
  - 商品を選ぶと、商品名・規格・入数・受注日（今日）・年間ID（納品日の年月-商品コード）・入庫名義が入る。ケースを打つと商品kg（入数×ケース）が、商品kg を打つとケースが入る（商品コード 999 は手で入れる）。
  - 受注ID は今までの一番大きい番号の次。入力日・登録時間も自動で入る。
  - Web 版で足したもの：「登録」ボタン（Access は画面を移るときに自動保存）、前・次・新規のボタン、名前から探す画面（欄をダブルクリック）。
  - 「しらいコード」の欄は使っていないので付けない（2026/10/20 確認）。
