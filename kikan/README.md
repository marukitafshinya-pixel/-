# 基幹システム Web 版（Access からの移行）

Access で作った基幹システム 8 つ（受注登録・丸北WorkStation・倉庫管理System・製造管理 丸北・製造計画・包装場管理System・WEB連携・手配出力用カレンダー）を、クラウドで動く Web アプリに移すためのフォルダ。

- 調査と計画：[../docs/access移行/](../docs/access移行/00_全体像.md)
- 進め方：[移行計画](../docs/access移行/10_移行計画（案）.md)

## フォルダ

| フォルダ | 中身 |
|---|---|
| `migrate/` | Access のデータを PostgreSQL に移す道具 |

## データの移し替え（migrate）

1. Access のファイルを `migrate/data/` に置く（ファイル名は `migrate/sources.json` のとおり）。このフォルダはリポジトリに入れない。
2. PostgreSQL を用意し、次を実行する。

```
cd kikan/migrate
PGURL=postgresql://ユーザー@ホスト/データベース python3 accdb_to_pg.py sources.json
```

- Access ファイル 1 つが、PostgreSQL のスキーマ 1 つになる（例：丸北WorkStation.accdb → `ws`）。
- 表と項目の名前は Access と同じ（`ws."TD_出荷"."輸送ID"` のように二重引用符で囲んで使う）。
- 何度でもやり直せる（実行のたびに、そのスキーマを作り直す）。
- 結果は `移し替え結果.md` に出る（表ごとに Access の件数と移した件数を比べる）。
- 必要なもの：mdbtools（`mdb-tables`・`mdb-schema`・`mdb-export`）、psql、Python 3。

## 書き出した CSV からの取り込み（csv_to_pg）

Access の画面側ファイルで `ExportTables`（表を CSV と fields.txt に書き出すプログラム）を動かして作ったフォルダを取り込む。

```
cd kikan/migrate
PGURL=... python3 csv_to_pg.py --fe 受注登録FE --dir 書き出したフォルダ
```

- fields.txt の型で表を作り、同じ名前の CSV を入れる。
- リンクしている表は、本来の持ち主のスキーマに入れる（例：受注登録FE の「TD_出庫」→ `soko."TD_出荷"`）。対応は `links/画面側ファイル名.json`（画面側ファイルの中の情報から作ったもの）。
- 画面側ファイルの中の表は、`sources.json` でその画面側ファイルに割り当てたスキーマ（例：`juchu_fe`）に入れる。
- ほかのシステムの表がいっしょに書き出されていて、すでに取り込んだものを上書きしたくないときは `--skip-schemas ws,soko` のように指定する。

## Excel で保存した CSV からの取り込み（excel_csv_to_pg）

Access の表を Excel に貼り付けて CSV にしたもの（型の情報がないもの）は、同じ形の表の型を借りて入れる。

```
PGURL=... python3 excel_csv_to_pg.py --csv 倉庫管理の受注.csv --table soko.TD_受注 --like juchu.TD_受注
PGURL=... python3 excel_csv_to_pg.py --csv 転売品管理の受注.csv --table tenbai.TD_受注 --like juchu.TD_受注
PGURL=... python3 excel_csv_to_pg.py --csv 原料管理の出荷.csv --table genryo.TD_出荷 --like soko.TD_出荷
```

- 日付（13-Oct-26 など）・TRUE/FALSE・カンマや ¥ の付いた数字を読み替える。入れる前に表を作り直す。
- `--like` の表にない項目は、入っている値から型を決める（真偽・日時・数・文字）。全部空欄の項目は文字になる。

## Web アプリ（app）

| フォルダ | 中身 |
|---|---|
| `app/server/` | サーバー（Fastify・PostgreSQL）。ログイン、受注の API |
| `app/client/` | 画面（React）。Access の画面に近い見た目にしている |

```
cd kikan/app
npm install
npm run build                      # 画面を作る（dist/）
PGURL=... npm run create-user -- ログインID 名前 パスワード [admin]
PGURL=... npm start                # http://localhost:3000 で開く
```

- 表は Access と同じ名前のものを使う（例：`juchu."TD_受注"`）。Web 版だけで使う表（利用者・ログイン・設定）は `app` スキーマに置く（`server/schema.sql`）。
- 開発中は `npm run dev`（画面は http://localhost:5173）。
- 受注の削除には、Access と同じく合言葉が要る。合言葉はプログラムに書かず、サーバーを動かすときに `JUCHU_DELETE_PASSWORD` で渡す（今の Access と同じものにする。2026/10/20 確認）。渡していないときは削除できない。

### 画面の決まり（全部の画面で同じにする）
- **日付**の欄は、ダブルクリックで共通のカレンダー（Access の FSD_日付選択）が出る。祝日・第 2/第 4 土曜などの休み・会社の特休（TM_イベントスケジュール）は赤の下線、日曜は赤、土曜は青、今日は黄色。
- 共通コードには**運送会社**（`kyotsu="unso"`、FSD_運送会社選択）もある。
- **共通コード**（全システムで使うマスタのコード：得意先の短縮コード＝受注先・届け先・帳合先・入庫名義・取引先など、商品コード）が入る欄は、色を変える（うすいオレンジ）。ダブルクリックで、そのマスタ（得意先・商品）を名前から探す画面が出て、選ぶとコードが入る。
- 作り方：入力欄の部品（`client/src/formParts.tsx` の `Field`・`Combo`）に `kyotsu="tokui"`（得意先）か `kyotsu="shohin"`（商品）を付ける。これから作る画面も同じようにする（2026/10/21 利用者の依頼）。
- 相手先のコード（日本食研・SB などの側のコード）は共通コードではないので、この印を付けない。
- 探す画面は Access の FSD_得意先選択・FSD_商品名選択 と同じつくり：カナのボタン（全・ｱ行〜ﾜ行・1 文字ずつ）、文字（商品は探す項目を選べる）、商品は分類・原料・旧コード、得意先は地区・都道府県・グループ・保管で絞る。見出しを押すとその順に並ぶ。行をダブルクリック（または選んで［選択］）で決める。得意先は短縮コードでも探せる。

### できている画面
- ログイン、メニュー（受注管理）
- 受注先選択画面（FM_受注先選択画面）
- 受注検索（F_受注検索）：開いたときに、Access のメニューと同じく受注オートチェック（倉庫管理の出庫・名義変更から、納品日が 2 日前より後の受注に倉庫・出荷予定日・運送会社などを写す）をしてから表示する。検索と、チェック（完了消込・入力確認〜送品案内）の付け外し。押すとすぐ保存される
  - 「出力」：いま表示している条件の受注を Excel（受注検索.xlsx）にする。Access の出力と同じ 15 列・同じ見た目（見出しは太字・灰色、日付は 14-Oct-26 の形）で、受注ID の順。Access では「当日入力分」「キャンセル未処理」を押したあとの出力は前の条件のままになるが、Web 版は表示しているとおりに出す
  - 「入力確認」を押すと、付けても外しても、受注特定項目の備考があれば備考の前に足し、入力日を今日にする（Access と同じ。何度も押すと備考が重なるのも今のまま）。
- 販盛受注取込み（F_販盛インポート）：販盛からダウンロードした「受注実績一覧」の CSV を「ファイル参照」で読み込む。Access と同じ動き：
  - 開いたときに前の読み込み（T_販盛受注）を消す。読み込むと、販盛の伝票番号＋行、または重さ・受注番号・納品日で Access の受注と結びつけ、結びついていないものだけを出す。
  - 「選択」を付けて「受注取込み」で受注に入れる（商品は繁盛商品コード、届け先は繁盛納入先コードで読み替え。読込変換届け先コードを入れればそれを使う。隠語「販盛In」）。
  - Access と同じく、取り込み済みかどうかは確かめずに入れる（同じ行を 2 回取り込むと 2 件になる）。
  - 販盛のサイトからのダウンロード（販盛受注出力）は、社内のパソコンの自動入力で行う予定（準備中）。
- 販盛売上出力（F_販盛インポート売上）：「売上実績一覧」の CSV を読み込み、販盛の売上番号・行を受注に結びつける。一覧は受注日が 7 日前からの受注。販盛のサイトからのダウンロードと、販盛への売上の自動入力は、社内のパソコンで行う予定（準備中）。
- 単価チェック（F_販盛単価確認）：（2026/10/20：販盛からダウンロードした PRICE_INQUIRY 2,687 行を読み込み、Access の単価マスタと同じ中身になることを確認）販盛の単価マスタ（PRICE_INQUIRY）と売上実績一覧のファイルを読み込み、確かめる日を入れると、売上の Kg 単価を単価マスタの一番新しい単価（単位コード 1）と見比べ、違うものに印を付ける（赤い行）。参照Kg単価は単価マスタから選び直せる。Access と同じく、見比べるのは納品予定日がその日の売上、表示は売上日がその日の売上。一度付いた印は消えない。販盛のサイトからのダウンロードは、社内のパソコンの自動入力で行う予定（準備中）。
- SB受注取り込み（F_エスビー受注インポート）：SB の受注（Windows アプリのテキスト CSV）を「ファイル参照」で読み込み、「番号認識」（または行の「選択」）で受注に取り込む。工場品目の先頭 6 けたを相手先商品マスタで、納入先を相手先届け先マスタで読み替え、受注元は 357、受注区分は備考が「名義変更」なら 2、ほかは 1。Access と同じ動き：
  - すでに取り込んだ受注（オーダーNo＝年間ID・商品コード・商品kg が同じ）は「●:取込み済み」として飛ばす。Access ではこの確かめが働かず二重に取り込めたが、利用者の依頼で直した（2026/10/20）。
  - 納入先・受注先が見つからない、入数が 0 のときは、そこで止まる（それまでに入れた行は残る）。
- 発注依頼（F_受注元選択 → F_発注書印刷／日本食研は F_日本食研発注書印刷）：受注元を選び、納品日・届け先・受注番号・商品・商品kg を入れると、条件にすべて合う受注の発注書を別の画面に出す（ブラウザで印刷）。Access と同じく、納品予定日を入れるとそのまま印刷に進む。日本食研は相手先のコードで選び、自社のコードに読み替える。
  - ユーザー追加・削除で受注元のボタンを増減（削除は合言葉が要る）。
  - 発注書（R_発注依頼）は、いただいた見本と同じ並び（A4 横）。受注検索の各行の「印刷」からも、その受注の発注書を出せる（伝票発行の代わり。2026/10/21 利用者の決定）。
  - 宛先（Access ではプログラムに書かれていたもの）は表（app."発注依頼書_宛先"）に移した。担当者の名前と、いちばん下の自社の名前・住所・電話番号は、プログラムに書かず、印刷画面の「宛先の設定」で入れる。
- 特定商品表示（FM_特定商品表示）：受注特定項目（商品・届け先ごとの注意書き）の一覧。［編集］で合言葉を入れると直す・足す・消すができる。
- 受注グループマスタ（FM_受注先マスタ登録）：受注先選択画面のボタン・受注先の一覧のもとになる表（TM_受注先マスタ）。Access と同じく開くときに合言葉が要る（`JUCHU_MASTER_PASSWORD`）。丸北北海道（受注区分 1）・大阪丸北（629）、取引元、届け先で絞り、表の中で直す・足す・消すができる。コードを入れると名前が入り、受注先を変えると道内区分（コードの頭が 1）も入る（Access と同じ）。
- 合言葉（特定商品の編集・発注依頼の受注元の削除）は、Access と同じものをサーバーを動かすときに `JUCHU_EDIT_PASSWORD` で渡す（プログラムには書かない）。
- 新しく入れる受注の既定値：Access の表の既定値に合わせ、初回登録chk はなし（「入力確認」を押したときに入る）、入庫名義ID 1、受注グループID 0、残ケース 0、商品コード1・届け先コード1 0 など。登録時間は Access と同じ形（2026/10/09 9:02:01）。
- 受注訂正（FM_受注訂正）：受注検索で処理コード（TM_枝処理マスタ：00 通常・0１ 訂正入力・02 追加受注・03 キャンセル・99 その他）を 0１〜03 にすると開く。Access と同じ動き：
  - 「閉じる」で、右の訂正の値をこの受注・WorkStation／倉庫管理／転売品管理の受注の写しに書き、まだ確定していない出荷（chk なし）に「受注訂正」の知らせを立てる。「やめる」は何もしないで閉じる。
  - 備考の先頭に「どこを直したか＋に訂正」を足す。いくつ直しても、最後に見つかった 1 か所だけが書かれる。
  - 引き取り区分の訂正の欄は空欄で始まる（選ばなければ今のまま）。
  - 隠語は、Access では訂正のたびに消えていた（「販盛In」の印がなくなる）が、Web 版では残す（2026/10/20 確認。不具合の例外として直した）。
  - Access の「TD_受注_訂正履歴」は表がなく、今も書かれていないため、Web 版でも書かない。
  - 倉庫管理・転売品管理の受注の写し（TD_受注）は、利用者から受け取った CSV で取り込み済み（2026/10/20：倉庫 178 件・転売 126 件）。転売品管理はごくまれに使うので、転売品管理の写しを直す動きも残す（2026/10/20 確認）。
- 受注登録（FM_受注登録_届け先指定）：新しい受注の入力・直し・削除。Access と同じ動き：
  - 受注番号・届け先コード・商品コード・ケース・商品kg・納品予定日を 2 回打って、違っていれば保存しない（片方が空欄のときは確かめない。Access と同じ）。
  - 受注番号が空欄なら「年月日＋商品コード＋届け先コード」で作るか聞く。
  - 商品を選ぶと、商品名・規格・入数・受注日（今日）・年間ID（納品日の年月-商品コード）・入庫名義が入る。ケースを打つと商品kg（入数×ケース）が、商品kg を打つとケースが入る（商品コード 999 は手で入れる）。
  - 受注ID は今までの一番大きい番号の次。入力日・登録時間も自動で入る。
  - Web 版で足したもの：「登録」ボタン（Access は画面を移るときに自動保存）、前・次・新規のボタン、名前から探す画面（欄をダブルクリック）。

### 丸北WorkStation（作っている途中）
- 進め方（2026/10/21 了承）：① 出荷明細票の本体 → ② 明細の詳細・受注読込・インポート → ③ 在庫の割り当て（希望在庫・在庫選択・配車割付・年間受注割振り） → ④ 帳票（入庫依頼書・積込み個数確認書・集荷パレットチェックリスト・積込み前点検表・荷台積載イメージ図など。見本受け取り済み）。
- ① 出荷明細票（FM_出荷明細票）：出荷日の移動（◀▶・カレンダー）、便の移動（1/2 など）、新しい便・便の削除（合言葉）、手配・帳合・輸送の運送会社、車番（全角にする）、積込・丸北の時刻、輸送区分などの区分、集荷日・セット温度・担当者、通知の件数、割付前データの知らせ、明細の一覧と合計。輸送の運送会社を変えると、Access と同じく区分などの初めの値が入る。明細の直し・詳細・在庫の割り当ては ②③ で作る。
- ② 明細の詳細（FSD_出荷明細2）：出荷明細票の「詳細」から開く。同じ便の明細を ◀▶ で移る。Access と同じ動き：
  - 届け先を変えると、届け先の受付時間を備考に足し、運賃振分け（C_レコード別条件運賃振分け：入庫先商品別名義条件から運賃振分区分・運賃請求・入庫後名義、倉庫あての取引元・取引帳合）をする。受注品の届け先を変えるときは受注ID を入れて確かめる。
  - 出荷場所を変えると、在庫を読み込んでいない行は入庫前名義を出荷場所条件の名義にする。ケースから kg、kg からケース、製造日から賞味期限（品質保持期間・日付差、うるう年の決まりも同じ）を出す。ケースを変えると受注の残ケース（WorkStation の受注の写し）を出し直す。
  - 登録済み（chk）の行は、ふだんは直せない。［訂正］を押してから欄を押すと、理由（訂正科目）を選んで直し、訂正履歴（TD_訂正履歴管理）に残す。
  - 削除：OK で削除（登録済みは消せない）、キャンセルで便からはずす（あとで読み込み直せる）。
  - 入庫後名義を 658（寿預かり）にしたときに備考に足す一文は、人の名前を含むので、プログラムに書かず app."設定" の「寿預かりの備考」に入れる。
  - 商品コードを変えるには在庫の読み込み（③）が要るので、今は直せない。
- ② インポート処理（F_インポート処理）：出荷明細票の「インポート処理」から。倉庫管理・転売品管理・原料管理の出荷（出荷日で絞る）から行を選び、この便の出荷に入れる（Access の CC_出荷to出庫）。インポート場所ID は 倉庫管理 2（認識ID「S_」＋在庫ID、パレット枚数＝ケース÷パレット単位1）、転売品管理 8（取り込み元に丸北輸送ID を書き戻す）、原料管理 4（認識ID「G_」＋在庫ID、取り込み元にインポート先出庫ID を書き戻す）。
  - Access と同じく、同じ行を二度取り込める（幹線・小口の重なりの元）。Web 版では「取込済」の列で、すでに WorkStation にあるかを見せ、二度目のときは確かめる。
  - 原料管理の出荷（TD_出荷）は Excel の CSV から `genryo."TD_出荷"` に入れた（137 行）。受注読込（F_受注検索）は次に作る。

### 利用者に確認して決めたこと
