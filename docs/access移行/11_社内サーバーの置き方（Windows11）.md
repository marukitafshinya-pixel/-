# 社内サーバーの置き方（Windows 11 のパソコン 1 台）

基幹システムの Web 版を、社内の Windows 11 のパソコン 1 台（以下「サーバーのパソコン」）に置いて、
社内のほかのパソコンからブラウザで使えるようにする手順。まずは実データの写しで試すためのもの。

- サーバーのパソコンは、電源を入れたままにしておく。
- ほかのパソコンには何も入れない。Edge か Chrome で開くだけ。
- この手順で入れたデータは Access とは別のもの。ここで入力しても Access には入らない（試しのあいだは）。

かかる時間の目安：1〜2 時間（ダウンロードの時間による）。

---

## 0. はじめに確かめること

1. **パソコンの名前**：［設定］→［システム］→［バージョン情報］の「デバイス名」。ほかのパソコンからは `http://この名前:3000/` で開く。メモしておく。
2. **同じネットワーク**：ほかのパソコンと同じ社内のネットワーク（同じ有線 LAN か、同じ Wi-Fi）につながっていること。
3. **ネットワークの種類を「プライベート」に**：［設定］→［ネットワークとインターネット］→ つながっているもの（イーサネットか Wi-Fi）→「ネットワーク プロファイルの種類」を **プライベート ネットワーク** にする。
4. **スリープしないように**：［設定］→［システム］→［電源］→「画面とスリープ」で、電源接続時に「スリープ状態にする」を **なし** にする（画面は消えてもよい）。
5. **管理者のアカウント**でサインインしておく（ソフトを入れるため）。

## 1. ソフトを 3 つ入れる

どれも無料。公式のページからダウンロードして、ふつうに入れる。

| ソフト | 入手先 | 選ぶもの・注意 |
|---|---|---|
| PostgreSQL（データベース） | https://www.postgresql.org/download/windows/ →「Download the installer」 | **16** の Windows x86-64。入れる途中で **postgres のパスワード** を決める（英字と数字だけにする。記号はつけない）。ポートは 5432 のまま。最後の「Stack Builder」はチェックを外して終わる |
| Node.js（アプリを動かすもの） | https://nodejs.org/ | **22** の LTS（Windows Installer .msi）。途中の選択はそのままでよい |
| Git（プログラムを取ってくるもの） | https://git-scm.com/download/win | 64-bit 版。途中の選択はそのままでよい |

- postgres のパスワードは、紙に書くなどして大切にしまっておく（あとで 2 か所に書く）。
- 入れ終わったら、パソコンを一度再起動する。

## 2. プログラムを取ってくる

1. スタートボタンを右クリック →「ターミナル」を開く。
2. 次を 1 行ずつ入れて Enter：

```
cd C:\
git clone -b claude/kind-pasteur-zxwugb https://github.com/marukitafshinya-pixel/-.git kikan-src
```

- GitHub のサインインの画面が出たら、リポジトリの持ち主のアカウントでサインインする。
- `C:\kikan-src` というフォルダができる。

3. 続けて、画面を作る：

```
cd C:\kikan-src\kikan\app
npm install
npm run build
```

（数分かかる。赤い字で「error」と出て止まったら、その画面の写真を送ってください）

## 3. データベースを作って、データを入れる

データは、Claude が試し用のデータベースから作った **バックアップのファイル（kikan.dump）** を受け取って入れる。
受け取ったら `C:\kikan\kikan.dump` に置く（フォルダ `C:\kikan` は自分で作る）。

ターミナルで：

```
cd "C:\Program Files\PostgreSQL\16\bin"
.\createdb -U postgres kikan
.\pg_restore -U postgres -d kikan --no-owner C:\kikan\kikan.dump
```

- そのたびに postgres のパスワードを聞かれるので入れる（入れても画面には出ない）。
- `pg_restore` で「warning」がいくつか出ても、最後まで進めば大丈夫。

## 4. 起動のファイルを作る

メモ帳で次の中身を書き、`C:\kikan\起動.bat` という名前で保存する（保存の画面で「ファイルの種類」を「すべてのファイル」、文字コードを「ANSI」にする）。

```
@echo off
cd /d C:\kikan-src\kikan\app
set PGURL=postgresql://postgres:ここにpostgresのパスワード@127.0.0.1:5432/kikan
set HOST=0.0.0.0
set PORT=3000
set JUCHU_DELETE_PASSWORD=受注の削除の合言葉
set JUCHU_EDIT_PASSWORD=受注の訂正の合言葉
set JUCHU_MASTER_PASSWORD=受注のマスタの合言葉
set MASTER_PASSWORD=マスタ管理の合言葉
set SOKO_PASSWORD=倉庫管理の合言葉
set WEB_RENKEI_KEY=長めの好きな文字列（30文字くらい）
if not exist C:\kikan\log mkdir C:\kikan\log
call npm start >> C:\kikan\log\server.log 2>&1
```

- 合言葉は、今の Access と同じものにする。
- **このファイルにはパスワードが入るので、共有フォルダや OneDrive には置かない。** ほかの人に送らない。
- `WEB_RENKEI_KEY` は一度決めたら変えない（変えると、WEB連携で保存した相手先サイトのパスワードが読めなくなる）。

### ログインする人を作る

ターミナルで（パスワードの部分は自分のものに置き換える）：

```
cd C:\kikan-src\kikan\app
set PGURL=postgresql://postgres:ここにpostgresのパスワード@127.0.0.1:5432/kikan
npm run create-user -- ログインID 名前 パスワード admin
```

- 最後の `admin` を付けた人は管理者（ほかの人を足せる）。ふつうの人は `admin` を付けない。
- 試し用のデータには、試験用のログイン（test）も入っている。本番の前に消す。

## 5. 試しに動かす

1. `C:\kikan\起動.bat` をダブルクリック（黒い画面が出たまま動く。閉じると止まる）。
2. サーバーのパソコンの Edge で `http://localhost:3000/` を開き、ログインできるか確かめる。
3. 確かめたら、黒い画面を閉じて止める（次の 6・7 で、自動で動くようにする）。

## 6. ほかのパソコンから開けるようにする（ファイアウォール）

スタートボタンを右クリック →「ターミナル（管理者）」を開いて、次の 1 行を入れる：

```
New-NetFirewallRule -DisplayName "基幹システム Web 版" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow -Profile Private,Domain
```

- データベースの入口（5432）は開けない。データベースはサーバーのパソコンの中からだけ使う。

## 7. パソコンを起動したら自動で動くようにする（タスク スケジューラ）

1. スタートで「タスク スケジューラ」を探して開く →右側の「タスクの作成」。
2. ［全般］
   - 名前：`基幹システム Web 版`
   - 「ユーザーがログオンしているかどうかにかかわらず実行する」を選ぶ
3. ［トリガー］→「新規」→「タスクの開始」を **スタートアップ時** → OK
4. ［操作］→「新規」→「プログラム/スクリプト」に `C:\kikan\起動.bat` → OK
5. ［条件］→「コンピューターを AC 電源で使用している場合のみタスクを開始する」の **チェックを外す**
6. ［設定］
   - 「タスクを停止するまでの時間」の **チェックを外す**（外さないと 3 日で止まる）
   - 「タスクが失敗した場合の再起動の間隔」にチェック、1 分、3 回
7. OK を押し、Windows のパスワードを聞かれたら入れる。
8. パソコンを再起動して、ほかのパソコンの Edge で `http://パソコンの名前:3000/` が開けるか確かめる。

開けないとき：
- サーバーのパソコンで `http://localhost:3000/` は開けるか →開けなければ `C:\kikan\log\server.log` の最後のあたりを見る（写真を送ってください）。
- サーバーのパソコンでは開けるのに、ほかからは開けない → 0 の 3（プライベート）と 6（ファイアウォール）を確かめる。パソコンの名前で開けないときは、名前の代わりに番号（サーバーのパソコンで `ipconfig` と打って出る「IPv4 アドレス」）で開いてみる。番号で開けるなら、ルーターでその番号を固定してもらうとよい。

## 8. 毎日のバックアップ（OneDrive に保存）

メモ帳で次を書き、`C:\kikan\バックアップ.bat` で保存する（文字コードは ANSI）：

```
@echo off
set PGPASSWORD=ここにpostgresのパスワード
set D=%date:~0,4%%date:~5,2%%date:~8,2%
set OUT=%OneDrive%\基幹バックアップ
if not exist "%OUT%" mkdir "%OUT%"
"C:\Program Files\PostgreSQL\16\bin\pg_dump" -U postgres -h 127.0.0.1 -Fc -f "%OUT%\kikan_%D%.dump" kikan
forfiles /p "%OUT%" /m kikan_*.dump /d -30 /c "cmd /c del @path"
```

- 1 日 1 つ、`kikan_20261106.dump` のような名前でできる。30 日より古いものは消す。
- タスク スケジューラで、もう 1 つタスクを作る：
  - 名前：`基幹システム バックアップ`
  - ［全般］「ユーザーがログオンしているときのみ実行する」（OneDrive のフォルダを使うため、サーバーのパソコンには OneDrive の契約の人でサインインしたままにしておく）
  - ［トリガー］毎日、夜（例：21:00）
  - ［操作］`C:\kikan\バックアップ.bat`
- 次の日に、OneDrive の「基幹バックアップ」にファイルができているか確かめる。

### バックアップから戻すとき

（サーバーを止めてから。7 のタスクを右クリック →「終了」）

```
cd "C:\Program Files\PostgreSQL\16\bin"
.\pg_restore -U postgres -d kikan --clean --if-exists --no-owner "戻したいファイル.dump"
```

## 9. プログラムが新しくなったとき（Claude が直したあと）

1. タスク スケジューラで「基幹システム Web 版」を右クリック →「終了」
2. ターミナルで：

```
cd C:\kikan-src\kikan\app
git pull
npm install
npm run build
```

3. 「基幹システム Web 版」を右クリック →「実行」

- 表の形が変わるときは、起動したときに自動で直る（`server/schema.sql`）。データは消えない。
- 念のため、直す前の日のバックアップがあることを確かめてから行う。

## 10. 気をつけること

- **Windows Update の再起動**：再起動しても 7 の設定で自動で動き出す。業務中に再起動されないよう、［設定］→［Windows Update］→［詳細オプション］→「アクティブ時間」を業務の時間に合わせる。
- **停電・電源を切ったとき**：電源を入れれば自動で動き出す。
- **このパソコンが壊れたとき**：別のパソコンにこの手順で入れ直し、3 の代わりに OneDrive の最新のバックアップを入れれば戻る。
- **パスワードの入ったファイル**（起動.bat・バックアップ.bat）は、C:\kikan の中だけに置く。
- 社外から使うことはできない（社内のネットワークの中だけ）。社外からも使うなら、クラウドに移すときに考える。
