## 1. ひとことで言うと

- **製造の出来高（何を何ケース作ったか）を登録する** 小さなシステム。画面 18、プログラム約 7,200 行。
- 登録した出来高（入庫）は、丸北WorkStation が在庫として取り込む（**在庫の入口**）。
- 製造計画の計画数（共有Accessテーブル.accdb の生産計画）を読み、出来高の画面で計画数を直すと **計画側も書き換える**。
- 数が変わると、WorkStation の出荷データに「訂正」「出荷停止」などを直接書き込んで知らせる。
- 販盛（販売管理）に、製造日報をブラウザの自動操作で登録する。

## 2. つながり

| 相手 | 表 | 使い方 |
|---|---|---|
| 製造管理 丸北.accdb（自分のデータ） | 入庫（TD_入庫） | 出来高・包装の実績。主な表 |
| 共有Accessテーブル.accdb | 新規生産計画 | 計画数を読む・書き換える |
| 丸北WorkStation.accdb | 出荷、輸送計画 | 変更の知らせを書き込む／出荷履歴を読む |

- 商品・得意先などのマスタは、この画面側ファイルの中に写しがある（前日に入れ替えられていた）。

## 3. 画面と流れ

メニューで日付を選んでから各画面を開く（画面はメニューの日付を使う）。

| 画面 | 内容 |
|---|---|
| **出来高登録**（丸北北海道 工場 11） | 製造日の予定の行がある商品について、区分（タグ①〜⑧）ごとに計量した数（袋数）を入れる。ケース＝計量数 ÷ 規格枚数（切り捨て）、kg＝入数 × ケース。区分の追加・削除。最後の区分は、合計が計画数に合うよう自動で調整する |
| **生産登録**（包装日誌 工場 11）／**他工場 生産登録**（ふらの 191） | 包装日ごとの実績の入力。未包装の分（前回未包装分）を別の行に分け、包装したら取り込む。販盛への製造日報の登録ボタン（工場 11 のみ） |
| **計量数登録** | 他工場の計量日誌 |
| **生産予定入力** | 予定の行を作る。包装日＝製造日の翌日（土曜は月曜。ふらのは +1 日）。賞味期限を計算 |
| **取引先商品製造一覧** | 工場・得意先・商品・期間で、生産履歴・出荷履歴を表示・出力 |

### 主な決まりごと
- **数量確定フラグ** を付けた行を、WorkStation が在庫に取り込む（取り込み済みの印も付く）。
- 賞味期限＝製造日＋品質保持期間（年）＋日付差（うるう年の補正あり）。
- 検査区分＝カード札番号の範囲（開始No－終了No）。台車数＝計量数 ÷（冷凍パン入数 × 15 段、一部商品は 16 段）。
- 2026年3月に「各区分の半端を合わせて箱にする」ルールが廃止された（計算の前後が変わっている）。
- 閉じるときに検査日報（Excel）を作る。

## 4. 見つかった不具合・気になる点

1. 計画数を直したときの書き換えに **作業場（1工場・2工場）の条件がなく**、両方が同じ値になる。
2. ケースや kg を直接直しても、出荷への知らせが送られない（変数の宣言漏れ）。
3. 販盛への製造日報の登録は、1 回押すと 1 件だけ（繰り返しがない）。
4. 生産予定入力の箱詰枚数の計算が、ほかの画面と違う式になっている。
5. 出荷への知らせで照合に使う番号を上書きするので、2 回目以降は照合が合わない。
6. 「訂正」ボタンが開く画面がない。製造カレンダーは部品がなく開けない。
7. 「変更あり」の印が全員共通なので、最初に閉じた人が他の人の変更もまとめて知らせる。
8. 販盛のログイン情報がプログラムの中に書かれている。
9. ボタンの名前と開く画面が合っていない（「計量数登録」ボタン → 出来高登録 など）。

## 5. Web 化のときに考えること

- 「予定 → 計量 → 確定 → 在庫に取り込み → 変更の知らせ」の流れを、**状態の流れ** としてはっきり作る。
- 計画数との関係（出来高画面から計画を書き換えるか）を決める。
- 区分（タグ）を丸数字の文字で扱っている（⑨以上は扱えない）。番号で持つ。
- 販盛への製造日報の登録をどうするか（自動操作を続ける・CSV・手入力）。
