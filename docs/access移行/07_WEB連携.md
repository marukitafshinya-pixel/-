## 1. ひとことで言うと

- 物流の担当者が使う **外部の Web サービスへの自動入力（RPA）** 用のファイル。
- WorkStation・倉庫管理・受注登録のデータを読み、ブラウザ（Edge）を自動で操作して外部の Web に入力する。外部で振られた番号は、社内のデータに書き戻す。
- **最後の「登録」ボタンは、基本的に人が押す** 運用。
- 画面 18、プログラム約 5,200 行。2023年に作られ、今も直されている（日本食研の新システム MerQurius 対応は開発中）。

## 2. 相手の Web サービスと、やっていること

| 相手 | やっていること | 元のデータ | 書き戻し先 |
|---|---|---|---|
| **elixxi**（ニチレイの寄託者向け Web） | 入庫依頼の登録・訂正、出庫依頼の登録、入庫予定一覧の CSV 取得と照合 | 入庫：WorkStation の出荷／出庫：倉庫管理の出庫 | 受付番号は人が入力 |
| **ランテック**（運送会社） | 発注の入力、発注一覧 CSV の取得、送り状番号の照合 | 倉庫管理の出庫 | 倉庫管理の輸送計画に送り状番号 |

| **MerQurius**（日本食研の新システム） | 納入日程 CSV を取り込み、注文番号＋ロットで照合して、アップロード用 CSV を作る（開発中） | WorkStation の出荷 | なし |

### 主な決まりごと
- elixxi の入庫明細のまとめ方：ニチレイ大谷地（164）はタグごと、ほかはロット（製造日・賞味期限）ごと。名義によって寄託者を切り替える（丸北北海道／ふらの／大阪丸北）。
- elixxi の拠点・扱い便コードへの置き換え（大宮・船橋・大谷地で特別な付け方がある）。
- ランテックの備考欄に賞味期限を書く届け先（マスタあり）、大谷地の出庫で「○月○日 積み」と書く届け先（マスタあり）。
- 照合：elixxi の受付番号・ランテックの送り状番号について、「相手にあってこちらにない」「こちらにあって相手にない」「数が違う」を一覧にする。
- **受注への書き戻し**：倉庫や運送会社から返ってきた番号（運行指令No・車号）を受注に入れ、「FAX の返信を確認した」扱いにする。
- WorkStation の「入庫依頼書確認用」の表を、このファイルからも作り直している（同じ処理が 2 か所にある）。

## 3. 見つかった不具合・気になる点

1. 販盛の仕入の自動入力に、プログラムの書き間違い（If の閉じ忘れ）がある。動かない可能性が高い。
2. メニューの 2 つのボタン（販盛受注登録・Outlook 保存）は、呼び先がなくて動かない。
3. elixxi の受付番号から開く処理で、十勝だけ選べない。
4. 日本食研 Web-EDI の入力は、10 件目以降で画面の部品の名前が合わなくなるおそれがある。
5. ランテックの照合で商品コードを見ていない（数の合計だけで照合）。
6. elixxi の訂正登録で、削除する行を並び順で決め打ちしている（並び順が変わると、違う行を消す危険がある）。
7. Edge のドライバーの自動更新は、ダウンロード元が古い住所のままで、失敗している可能性が高い。
8. MerQurius 版は WorkStation の出荷しか見ないので、営業倉庫から出た分が抜けるおそれがある。
9. **ログイン情報を平文で保存している**：表の中（PC 名ごとのログイン情報）、プログラムの中（ランテック・日本食研・販盛）。

## 4. Web 化のときに考えること

- ブラウザの自動操作は、相手の画面が変わると壊れる。Web 化するなら次のどれにするかを、相手ごとに決める。
  1. 相手の **CSV 取り込み・API** を使う（あれば一番安定）
  2. サーバーや PC で自動操作を続ける（Playwright など）
  3. CSV を作って、人がアップロードする
- 販盛は **IE モード** が前提になっている。
- ログイン情報は、安全な保管場所に移し、パスワードを変える。
- 拠点・寄託者・扱い便などのコードの置き換えは、マスタにまとめる（今は 4 か所に重複して書かれている）。
- 古い試作・見本のプログラム（Outlook・HTTP の見本・test など）は移さない。
