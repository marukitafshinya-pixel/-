## 1. ひとことで言うと

- WorkStation の配車データを読んで、**自社手配の貸切便をカレンダーで見る**、**ニチレイ（LN）あての輸送手配表を Excel で作る**、**工場の保管庫が何トンになるかを予想する** ための小さなツール。画面 28、プログラム約 8,300 行（ただし大部分は WorkStation の古いコピー）。
- 包装場管理のファイルをコピーし、WorkStation の画面を足して作られている（2025年3月〜2026年4月）。

## 2. 使われている機能

| 機能 | 内容 |
|---|---|
| **配送予定カレンダー**（主画面） | 自社手配（運送会社 630）の貸切便（配達区分 4）を、LN 帳合（139）について月のカレンダーに表示。道内／道外の切り替え、祝日表示。日付をダブルクリックで、その日の配車画面（WorkStation のコピー）を開く |
| **保管庫トン数の予想** | 工場（11）の在庫＋製造予定（製造管理）−出荷予定（WorkStation）を 120 日分計算。カレンダーの日付を 36t／38t／40t で色分け。印刷もできる |
| **ニチレイ出荷詳細データ出力**（今使われている） | 便 × 集荷先 × 届け先 × 商品の手配表を Excel で作り、共有フォルダに保存 |
| **ニチレイ配車表出力**（LN 求車依頼） | 便ごとの手配表（2026年4月が最後） |
| **相手先コードの対応表** | 自社の届け先・運送会社の番号 → ニチレイ側の番号（届け先 19 件、運送会社 5 件） |

### 手配表の決まりごと
- 対象：出荷計画日の範囲、道内（地区 1）／道外、LN 帳合、未確定の出荷。
- 運行No は WorkStation で入れた車号、elixxi の受付番号は WorkStation の入庫依頼書確認用から引く。
- 番号の対応がないと **空欄のまま出力** される（警告なし）。
- **メールを送る処理はない**（メールのひな形 4 件はあるが使われていない）。Excel は人が手でメールに付けて送っていると思われる。
- 前回送った Excel と比べる処理は作りかけ（ボタンがない、出荷計画日しか比べない、比較の誤りがある）。

## 3. 見つかった不具合・気になる点

1. 保管庫の予想で、倉庫の番号が常に空になる（プログラムの誤り）。予想の印刷画面で、開始日と終了日が逆に渡されている疑い。
2. 道内・道外の判定が、カレンダーと出力で違う方法になっている。
3. 便ごとの出力（LN 求車依頼）に、動かない命令がある（コンパイルエラーの疑い）。ファイル名の日付を別の表から取っている。
4. **WorkStation の配車画面のコピーで、WorkStation の本番データを排他チェックなしで書き換えられる**。
5. 番号の対応表が WorkStation 側にも別にあり、中身が古い。どちらを正にするか決める必要がある。
6. 商品・得意先などのマスタはコピーで、更新は手作業。

## 4. Web 化のときに考えること

- 配車画面のコピーなどは捨て、WorkStation の配車画面に 1 つにまとめる。
- 残す機能：貸切便カレンダー、ニチレイ／LN あて手配表の出力、相手先コードの対応表、保管庫トン数の予想、送った内容の記録と比較（作り直し）。
- 手配表のメール送信を自動にするか、人が送るままにするかを決める。
