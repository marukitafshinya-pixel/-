## 1. ひとことで言うと

- このファイルは **「受注」の画面側** だけ。データ本体は共有フォルダの **別の Access ファイル 7つ** にある。
- 受注のほかに、**倉庫管理・丸北WorkStation・転売品管理・製造管理・製造計画・輸送管理** という別の Access システムがあり、受注データや商品・得意先マスタを **お互いに写し合って** 使っている。
- そのため、**受注だけを Web にすると、ほかの Access システムとのつながりが切れる**。どこまでを Web にするか（範囲）を最初に決める必要がある。

## 3. 今使われている機能（メインメニューから）

### 3-1. 受注の入力
- 入口は「受注先選択画面」。会社区分 → 取引先 → 受注先 の順に選ぶ。
- 取引先によって、**入力画面（伝票の形）が 6種類** に分かれる。分け方はプログラムに取引先の番号を直接書いている。

| 取引先 | 画面の特徴 |
|---|---|
| 日本食研 | 相手先の品番で入力。納品場所＝受注先。土曜納品の警告 |
| エスビー食品 | 相手先の品番・届け先コードを自社コードに置き換え。単価×kg、消費税も計算 |
| 和弘食品／北斗サプライ | 単価マスタから期間で単価を引く。消費税も計算。納品日の範囲チェック |
| 丸大 | 本社受注扱い。過去の受注から商品を選ぶ。「新潟条件」などの隠語 |
| ふらのソース | 決まった品目一覧から、チェックした品目をまとめて作る |
| それ以外 | 1件ずつ入力する汎用の画面（届け先指定） |

- 共通のしくみ
  - 選び間違いを防ぐため、最初に受注先の **電話番号** を打たせ、合わなければ画面を閉じる。
  - 受注番号・商品・kg・ケース・納品日を **2回入力** させて照合する。
  - kg は入数で割り切れないとエラー。ケース⇔kg は自動計算。
  - 統一受注ID＝「納品日の年月－商品コード」。受注番号がなければ「今日の日付＋商品＋届け先」で自動で作る。
  - 入庫名義は「名義条件マスタ」から、届け先・商品で自動で決める。

### 3-2. 受注の検索・訂正・確認
- **受注検索**：受注元・受注先・納品日・商品・番号で絞り込み。「当日入力分」「キャンセル分」。Excel に出力。
- 検索を開く前に、倉庫管理側から **出荷予定日・倉庫・運送会社・送り状No** を自動で取り込む（2026年3月に追加された処理）。
- **受注訂正**：変更前と変更後を備考に残し、4か所の受注の写しをすべて直す。まだ出荷が確定していない出荷データには「受注訂正」の知らせを立てる。
- **出荷実績の照会**：受注1件に対する出荷・出庫・転売・名義変更の実績を一覧する。
- 受注の状態は、いくつかのチェック欄の組み合わせで表している（完了、訂正・追加・キャンセルの区分、残ケース など）。

### 3-3. 販売管理システム（販盛）との連携
- 販盛は Web の販売管理システム。Access から **ブラウザを自動で操作**（Selenium・Edge の IE モード）してログインし、CSV をダウンロードしている。
  - **受注の取り込み**：受注実績一覧を取り込み、伝票番号で照らし合わせて受注に追加する。
  - **売上計上の確認**：売上実績一覧を取り込み、まだ売上になっていない受注を表示する。
  - **売上の自動入力**：販盛の売上入力画面に、途中まで自動で打ち込む（在庫の選択と登録は人）。
  - **単価のチェック**：販盛の単価マスタを取り込み、売上の kg単価と違う行に印を付ける。
- 販盛のログインID・パスワードが **プログラムに直接書かれている**。

### 3-4. そのほかの取り込み・帳票
- エスビー食品の Web 受注（CSV）の取り込み。
- 帳票：発注依頼書（宛先は商品で切り替え、FAX 返信の文言入り）、和弘食品専用伝票（専用用紙）、受注日報、売上日報、日本食研 web 確認表、ランテック 2か月未配達リスト（Excel）。
- 受注の曜日別分析（受注日基準・納品日基準）。

### 3-5. マスタの登録
- 商品（コードは 1〜9999 のいちばん小さい空き番号）、得意先（住所から都道府県と地区コードを決め、地区ごとの空き番号）、受注先、相手先商品・相手先届け先の置き換え表、届け先別の単価、名義条件。
- 登録すると、ほかの Access ファイルの写しにも配る。
- 修正にはパスワードが要る画面が多い（数字の固定パスワードが約70か所）。**ログインや利用者ごとの権限はない。**

## 4. このファイルにはあるが、ここでは動いていないもの

- **出荷・配車・在庫・保管料・しらい伝票・アレフ入庫依頼書** などのプログラムは、倉庫管理System／丸北WorkStation から写してきたもので、必要な表がこのファイルにないため **ここでは動かない**。本物は倉庫管理System などの側にある。
- 古い版・コピー（「old」「ver2」「のコピー」「確認用」など）が多数。
- 2017年5月から一度も直されていない画面（滝沢ハム、仕入、原料、本社受注、しらい など）。**今も使っているか確認が必要。**

## 5. 見つかった不具合（Web化のときに「そのまま」にするか決めたいもの）

1. 受注訂正・受注登録などから呼ばれる在庫計算の処理に、**受注データを全部消してしまうおそれのある命令** がある（条件がそろうと実行される）。
2. 和弘食品（1237）の画面の振り分けで列の位置がずれていて、**いつも「指定届け先」の画面** が開く。
3. エスビー食品・丸大の明細で、和弘食品の番号（1237）や北斗サプライの納品場所（1037）がコピーのまま残っている。
4. 販盛の受注取り込みとエスビー受注取り込みの **二重取り込みチェックが働いていない** 可能性が高い。
5. ふらのソースの受注番号に届け先コードが入らない。
6. 訂正の履歴を書く表がこのファイルになく、履歴が残っていない（残っても最後の1項目だけ）。
7. 名義条件が見つからないと、入庫名義が 0 で上書きされる。
8. 出荷の一覧（UQ_出荷）で、届け先コードと届け先名が入れ替わる行がある。
9. 自動取り込みで、運送会社を「受注ユーザー名」の欄に、輸送IDを「月間No」の欄に入れている（欄の使い回し）。
10. 着地日数（出荷予定日の計算）で祝日を考えていない。
11. 単価チェックの日付の扱い（30日前の1日分だけ取り込む／納品予定日と売上日の違い）が合っていない。
12. エラーが出ても止まらない書き方（On Error Resume Next）が多く、失敗に気づけない。

## 6. Web にするときに、そのままでは移せないもの

| 今のしくみ | Web での置き換え案 |
|---|---|
| 共有フォルダの Access ファイル 7つ | サーバー上のデータベース 1つにまとめる（写し合いをなくす） |
| 画面ごとの固定パスワード | 利用者ごとのログインと権限 |
| ブラウザ自動操作での販盛連携 | ① CSV をアップロードする形に変える、または ② サーバーで自動操作を続ける。販盛に API や定期出力があるかも確認 |
| Excel を開いて書き込む帳票 | サーバーで Excel / PDF を作ってダウンロード |
| Access の帳票（専用用紙の伝票など） | 印刷用の画面（用紙に合わせて位置を調整） |
| 取引先の番号を直接書いた画面の分け方 | 「伝票の形」をマスタで設定 |
| PCごとの OneDrive・共有フォルダのパス | 不要になる（ファイルはアップロード・ダウンロード） |
| 地図・音声合成の部品（ActiveX） | 使っていないので廃止 |

## 7. 決めていただきたいこと

1. **範囲**：受注だけを Web にするか、つながっている Access システム（倉庫管理・WorkStation・転売品管理・製造・計画・輸送）も含めて Web にするか。
   - 受注だけの場合、しばらくはほかの Access が受注データを読み書きできるように、**Web と Access の間でデータを行き来させるしくみ** が必要になる。
   - 全部の場合は、ほかの Access ファイル（画面側）も調べる必要がある。
2. **置き場所**：社内サーバーか、クラウドか（外から使う必要があるか）。同時に使う人数。
3. **不具合**：「仕組みそのまま」の中で、5章の不具合は直してよいか（おすすめは「直す」）。
4. **使っていない画面**：4章の画面（滝沢ハム・仕入・原料・本社受注・しらい など）は今も使っているか。
5. **販盛との連携**：ブラウザ自動操作を続けるか、CSV のアップロードにするか。
6. **データ**：本番のデータ（7つのバックエンドファイル）をいつ・どう受け取るか。移行の練習には写しが必要。

---

## 8. 進め方の案

1. 上の「決めていただきたいこと」を決める。
2. 範囲に入るほかの Access ファイル（画面側・データ側）を受け取って、同じように調べる。
3. データの形（表と項目）を Web 用に設計し、Access のデータを移すしくみを作る。
4. よく使う画面から作る：受注先選択 → 受注入力（汎用）→ 受注検索 → 訂正 → 取引先ごとの伝票 → 取り込み → 帳票 → マスタ。
5. 画面ごとに、Access と同じ結果になるかを照らし合わせる。
6. しばらく並行して使い、問題がなければ切り替える。

## 付録：調べ方（次に作業する人向け）

- `mdbtools` で表の一覧・定義・クエリ、`MSysAccessStorage` から VBA を取り出し、`oletools` で復元した。
- `mdb-queries` は `LC_ALL=C.UTF-8` にしないと日本語の名前で失敗する。また取り出した SQL は **JOIN の条件と GROUP BY が抜ける** ので、正確な SQL は Access で `CurrentDb.QueryDefs(i).SQL` を書き出して確かめる。
- 画面の配置（ボタンや入力欄の位置）は取り出せていない。画面の見た目は、Access で開いたスクリーンショットをもらうのが確実。
