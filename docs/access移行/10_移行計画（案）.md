## 2. 作り方の方針

### 2-1. データベース（今と同じ形で 1 つにまとめる）
- クラウドのデータベース（PostgreSQL）を 1 つ用意する。
- **表と項目の名前は Access と同じにする**（TD_受注、TD_出荷、TD_在庫、TM_得意先マスタ… 項目名も日本語のまま）。
  - 今のデータをほぼそのまま移せる。
  - **範囲外の Access（丸北商品推移・輸送管理・転売品管理・原料管理・仕掛原料管理・検査結果登録・Accessマスタ管理 など）も、ODBC でクラウドのデータベースにつなぎ直せば、今の画面のまま使い続けられる**（リンク先を変えるだけ）。
- 今「写し」で持っている表（受注の 4 つの写し、各システムのマスタの写し）は、まず **今と同じように別々の表として持つ**（不具合も含めて今の動きのまま）。1 つにまとめるのは改善の段階で行う。
- ほかのシステムのデータを直接書き換える処理も、同じデータベースの中の書き込みとして、そのまま再現する。

### 2-2. 画面
- ブラウザで使う Web アプリ（Edge／Chrome）。ログインして使う。
- 画面の並び・項目・ボタンは、**今の Access の画面にできるだけ近づける**（利用者が迷わないように）。
- 画面の見た目は取り出せていないので、**よく使う画面のスクリーンショットが必要**。

### 2-3. 帳票・Excel
- 帳票（82）は、サーバーで PDF を作ってブラウザで印刷する。今の帳票と同じ並び・文言にする（**今の印刷物の見本が必要**）。
- Excel 出力は、今のひな形（テンプレート）に書き込んでダウンロードする（**ひな形のファイルが必要**）。
- 札・ラベル（包装札・仕掛札・色紙・手差し）は、どのプリンターで印刷しているか確認が必要。

### 2-4. 外部 Web への自動入力（RPA）
- elixxi・ランテック・日本食研・MerQurius への自動入力は、サーバーの自動ブラウザ（Playwright）で再現する。
- **販盛は Edge の IE モードが前提** のため、クラウドの Linux サーバーでは動かない。次のどれかが必要：
  1. 社内の Windows パソコン 1 台に自動入力の役目を残す（クラウドのデータを読んで動く）
  2. クラウドに Windows のサーバーを用意する
- ログイン情報は、暗号化して保管する（今の平文の保存はやめる。パスワードの変更をおすすめ）。

### 2-5. 不具合の扱い
- 方針どおり、今の動きのまま作る。
- **ただし、データを消してしまう・戻せなくなるものだけは、例外として止めることを提案**（下の 3 件）。動きを変えるのではなく、「実行しない」だけにする。
  1. 受注を全部消してしまうおそれのある命令（受注登録・WorkStation の「受注割付」「受注訂正」など）
  2. 在庫の「元に戻す」で、つながりを消してしまうおそれ（WorkStation・倉庫管理）
  3. 包装場の「商品マスタの寸法を入れる処理」が終わらなくなるもの
- ほかの不具合（二重取り込み、1 便の完了で全便が完了扱い、など）は今のまま再現し、一覧にして改善の段階で直す。

## 3. 進め方

| 段階 | 内容 | 確認していただくこと |
|---|---|---|
| 0. 準備 | クラウドの契約先を決める。データ側ファイル（BE）の写しを受け取る。画面のスクリーンショット・帳票の見本・Excel のひな形を集める | 置き場所・費用 |
| 1. データの移し替え | データベースを作り、Access のデータを移すプログラムを作る。**何度でもやり直せる** ようにする | 件数・中身が合っているか |
| 2. 画面・処理 | システムごとに作る（受注登録 → WorkStation → 倉庫管理 → 製造計画・製造管理 → 包装場 → 手配出力用カレンダー → WEB連携） | 各システムができた時点で、仮想環境で触って確認 |
| 3. 帳票・Excel | 帳票 82 と Excel 出力 | 今の印刷物と並べて確認 |
| 4. 仮想環境での確認 | 本番データの写しで、**Access と同じ操作をして同じ結果になるか** を確かめる（数日〜数週間、並べて動かす） | 実際の業務の流れで確認 |
| 5. 切り替え | 切り替え日を決めて、最新のデータを移し、8 つまとめて Web に切り替える。範囲外の Access は、つなぎ先をクラウドに変える | 切り替え日 |
| 6. 改善 | 不具合の修正、写しの統合、手作業の自動化 など | 優先順位 |

- 量が多い（残す機能 約 80、帳票 82、元のプログラム約 13 万行）ため、**数か月単位** の作業になる。段階 1 と 2 の最初（受注登録）ができた時点で、全体のおおよその期間を出し直す。

## 4. 必要なもの

1. **データ側ファイル（BE）の写し**：受注登録.accdb、丸北WorkStation.accdb、倉庫管理System.accdb、製造管理 丸北.accdb、製造計画.accdb、共有Accessテーブル.accdb、包装場管理System.accdb。WorkStation などがつないでいる 転売品管理・原料管理2・仕掛原料管理・丸北商品推移 のデータ側ファイルも（つなぎ直しの確認用）。
2. **よく使う画面のスクリーンショット**（システムごとに主な画面）。
3. **帳票の見本**（残す 82 の帳票の、今の印刷物か PDF）。
4. **Excel のひな形**（受注検索・売上出力・週間予定表・保管賃月報・しらい伝票 など）。
5. **クラウドの契約**：費用は使う量によるが、データベースと Web アプリで月に数千円〜数万円程度が目安。会社として契約する（請求先）必要がある。
6. 販盛の自動入力をどこで動かすか（社内の Windows パソコンか、クラウドの Windows サーバーか）。
