# 丸北WorkStation（Access）調査報告

- 調べたファイル：`丸北WorkStation FE.accdb`（画面側のファイル。マスタなど一部のデータが入っている）
- 調べ方：画面・帳票・プログラム（VBA）・クエリを取り出して読んだ。何も実行・変更していない。
- この報告には、パスワード・サーバーの場所（IPアドレス）・個人名・電話番号を書かない。
- コードの中の番号（短縮コード）は、得意先マスタの「短縮コード」。倉庫・届け先・名義・取引先に共通の番号。

## 1. ひとことで言うと

- 丸北WorkStation は **出荷・配車・在庫の中心** のシステム。
- 「受注を選ぶ → 在庫を古い順に引き当てる → 出荷の行を作る → 車（配車）に割り付ける → 積み順を決める → 帳票を出す → 積込確認で在庫を減らす」までを受け持つ。
- 受注登録・製造管理・製造計画・倉庫管理・転売品管理・原料管理2 など、**ほかの 9 つのシステムのデータを読み書き** している。

## 3. 今使われている主な機能

### 3-1. 配車（出荷登録）— いちばん使う画面
- 1 台の車（1 運行）＝「輸送計画」1 行、荷物 1 行＝「出荷」1 行。出荷が車に割り付いていない間は「未割付」。
- 日付ごとに車を追加し、運ぶ会社・手配する会社・帳合の会社、車番、車両の種類、温度などを入れる。
- 出荷の行を車に割り付ける方法は 4 つ。
  1. 割付前の出荷行を選んで載せる（受注読込）
  2. 受注検索から作る（3-2）
  3. 倉庫管理・転売品・原料のシステムから取り込む（3-7）
  4. 在庫から選んで直接作る
- **積みすぎのチェック**：車番ごとの最大積載量と、出荷の重さの合計を比べて赤く表示。
- **パレット枚数**：ケース数 ÷ 商品ごとのパレット単位（切り上げ）。運送会社×車両の種類ごとの最大枚数がある。
- 削除は固定パスワードが必要。

### 3-2. 受注から出荷を作る（割付）
- 受注登録の受注を、このシステムの受注の写しに取り込んでから選ぶ（新しい番号の受注だけ追加。あとで直した内容は入らない）。
- 選んだ受注について、在庫を **古い順** に引き当てて出荷の行を作る。
  - 通常の受注：賞味期限 → タグ → 入庫No → 製造日 → 入庫日 の順
  - 年間受注・本社：製造日 → 賞味期限 → タグ → 入庫No → 入庫日 の順（**順番が違う。仕様か確認が必要**）
  - 出荷停止の在庫は飛ばす。在庫がなければ数量を入れて在庫なしで作ることもできる。
- 出荷の行には、取引元・帳合・届け先・名義・運賃の振り分け（本社受注なら大阪丸北 629、それ以外は丸北北海道 1）を自動で入れる。名義と運賃は「入庫先商品別名義条件」（約 790 行、通称ユーザーカード）で決まる。
- 受注側の残ケースを計算し直し、受注登録へ書き戻す。
- この割付の処理は **8 つ以上の画面に少しずつ違う写し** がある。

### 3-3. 本社（大阪丸北）の年間・月間受注
- 届け先 × 商品グループ × 月（年間は「yy00」）ごとの「受注残表」を持つ。
- 受注残 ＝ 前月繰越 ＋ 調整 ＋ 受注数 −（出荷済み ＋ 出荷見込み）
- 画面で商品を選ぶと、当月の製造数・出荷・在庫・前月在庫残などを並べて表示し、そこから在庫を割り付けて出荷を作る。
- 大阪受注登録：大阪分の受注数を kg で入れる。
- 大阪発注割振り：製造の出来高や在庫を、過去の届け先に割り振って「本社発注書」を印刷する（自動発注No＝日付＋商品グループ＋届け先）。

### 3-4. 積み順・届け順・積荷情報
- 車ごとに、届け先 × 出荷元でまとめて **届け順と積込順（逆順）** を自動で付け、手で直せる。
- 積荷情報：届け先ごと・集荷場所ごとの重さの合計と、集荷用チェックリスト（パレット単位で行を分ける）を作る。
- **積載イメージ**：段ボールの寸法から、トラックの荷台（幅・高さ・長さ）に何列何段で積めるかを計算し、図にして印刷する。
- **パレット輸送**：パレットを荷台の左右の枠に割り付ける画面（一覧から枠へ置く操作）。倉庫のパレット配置図もある。

### 3-5. 帳票
- 車両点検表、積込確認書、集荷用チェックリスト、積載イメージ図、配車組合せ表
- 入庫依頼書（冷蔵庫ごと・輸入・ドラム・ふらの・チタカ など）、送品案内書（冷蔵庫／ユーザー／無地）、出荷通知書、輸送依頼書、出荷予定明細票、在庫表
- 名義によって **送り主の会社名・住所・FAX が切り替わる**（丸北北海道／JAふらの／大阪丸北／丸北）。住所などは帳票の中に直接書いてある。
- 入庫依頼書は、送ったあとに数量や車番が変わると「変更」「削除」の印を付けて知らせる。
- 毎日の帳票をまとめて出す画面（前回の報告日の翌日から今日までを印刷）。
- 条件を選んで表を自動で作る「抽出帳票」（条件を保存できる）。

### 3-6. 在庫
- 在庫は **ロット（倉庫 × 商品 × 製造日 × 入庫日）ごとの行** で持つ。名義（誰の持ち物か）と保管場所は別に持つ。
- 在庫の入口：製造管理の入庫（数量確定のもの）。出口：出荷の「積込確認」。
  - 積込確認にチェックすると、その場で在庫を減らす。届け先が預け先の冷蔵庫なら、そこに新しい在庫行を作る（＝移動と名義の付け替え）。
  - 日々の締め（在庫更新）もあり、入庫の取り込み・出荷の反映・確認・取り消しができる。
- **予定在庫（架空在庫）**：実在庫＋まだ取り込んでいない入庫（生産予定）−まだ反映していない出荷。受注の割付に使う。
- **検査**：区分（1〜4 検査待ち、5 出荷停止）と合否（合格で製品に戻す）。結果を出荷の行と仕掛原料管理にも書き込む。
- 在庫の訂正・振替（サンプル・原料化・破損・廃棄・製品化・出荷停止）、保管場所の移動、パレットごとの棚卸。
- 計量数の登録（製造管理の入庫の数を直接直す）。賞味期限＝製造日＋品質保持期間（年）＋日付差。

### 3-7. ほかのシステムからの取り込み・出力
- **倉庫管理（営業冷蔵庫）の出庫** → 写してから選んで出荷に追加（印 S_）
- **転売品・原料の出荷** → 相手の表を直接選んで追加し、相手に番号を書き戻す（印 G_ など）
- **売上用の出荷データ** → 区分（丸北北海道／その他／倉庫／名義変更／預かり）ごとに Excel のひな形に書き込み保存（2022年3月から動いた記録がない）
- しらい便の伝票、パレット積込確認書、週間入庫予定表 → Excel のひな形に書き込み

### 3-8. マスタ
- 商品（約 290 件）、得意先（約 1,700 件：届け先・倉庫・工場・運送会社などすべて）、運送会社（約 260 社）、車番ごとの積載量、名義・運賃の振り分け条件（約 790 件）、相手先の商品・届け先コードの置き換え、パレット・段ボール寸法、集荷先ごとのパレット設定、祝日カレンダー など。
- 得意先の新しい番号は「地区コード＋空き番号」。
- 編集は固定パスワードで「読み取り専用」を外す方式。ログイン・利用者ごとの権限はない。
- **マスタはこの画面側ファイルの中にある。ほかのシステムも同じ名前のマスタを別々に持っていて、自動でそろえる仕組みはない。** 前日（2026/10/16）に 5 つのマスタがまとめて入れ替えられていた（手で入れ替えていると思われる）。

## 4. このファイルにはあるが、動いていない・使われていないもの

- 売上報告・仕入帳・資材マスタ・製品仕様書・送り先マスタ・ふらの買取・本社年間（旧版）・OMF 年間・elixxi への入庫登録 など：参照する表やプログラムがなく動かない。
- 保管料・入出庫料の計算：料金表がすべて 0 で、実質使われていない。
- 古い版・コピー（「old」「のコピー」「ver」）、2017 年から更新のない画面が多数。
- 存在しない画面・表を開こうとする箇所が 20 以上。

## 5. 見つかった不具合（影響の大きいもの）

1. **「受注割付」画面の「選択」で、このシステムの受注の写しが全部消えるおそれ**（受注登録で見つかったものと同じ命令）。
2. **在庫のバックアップと「元に戻す」が効いていない**（コピーしているのは表へのつながりだけで、データは写っていない）。戻したつもりで二重に計上する危険がある。
3. 在庫の締めをやり直すと、届け先側の入庫が二重になるおそれ。
4. 期間を指定した在庫集計（大阪発注割振り（在庫））で、まだ在庫に入っていない出来高が消える。
5. 出荷明細の詳細画面で、商品を入れると **先頭の商品の規格・入数で上書き** される（kg も間違う）。
6. 運賃の自動振り分けを日付単位で動かすと、最初の届け先の条件がほかの行にも使われる。
7. しらい便の絞り込みが常に空になる書き方（実際に使えているか確認が必要）。
8. 年間受注の集計で、条件が矛盾していて「見込み」が常に 0 になる箇所、期間が逆向きになる箇所。
9. 「更新中」の印が画面側ファイルの中にあり、複数の人が同時に在庫の締めをしても止められない。
10. 画面での選択の印（抽出区分）を共有のデータに書いているので、同時に作業すると混ざる。
11. エラーが出ても止まらない書き方が多く、失敗に気づけない。

## 6. Web にするときのポイント

| 今のしくみ | Web での置き換え案 |
|---|---|
| 受注が受注登録と WorkStation（と倉庫管理・転売品）に写しで存在 | 受注を 1 つにまとめ、残数は出荷から毎回計算 |
| マスタが各システムの画面側ファイルに別々にある | 1 つのデータベースにまとめる（どれを正にするか決める） |
| 在庫の残数を足し引きで保存＋日々の締め | 入出庫の記録から在庫を出す方式にまとめ、締めは記録として残す |
| 作業用の表を毎回消して作り直す・選択の印を共有の表に書く | 利用者ごとの計算・画面の中での選択にする |
| 割付処理の写しが 8 つ以上 | 1 つの共通処理にまとめる（引き当ての順番は設定で） |
| Excel のひな形への書き込み・帳票に直接書いた住所 | サーバーで Excel／PDF を作る。送り主の情報はマスタに |
| 積載イメージ・パレット枠の図 | 画面上の図（ドラッグして置ける）として作り直す |
| 固定パスワード | ログインと権限 |

## 7. ほかのシステムと合わせて決めたいこと

- 引き当ての順番（賞味期限が先か、製造日が先か）を統一するか。
- 年間受注の年度の始まり（コードは 9 月、データは 10 月のものがある）。
- 動いていない機能（売上報告・仕入帳・資材マスタ・仕様書・ふらの買取・保管料 など）を、Web で作り直すか、やめるか。
- 個人の住所録（専務関連）は Web に移さない方がよい（個人情報）。
